# Phase 14 — Specification Contradiction Log (M0)

*Status: open. Per the implementation brief's critical rule: when implementation reveals a genuine contradiction in the frozen specification, work stops at that point, the contradiction and its smallest resolution are documented here, and nothing is silently redesigned. Entries below were found during M0 extraction (pre-implementation) and resolved at the smallest possible scale without touching the frozen grammar.*

| G-14 | §13.1's normative example declares `divide` with `returns a number` and `give back top divided by bottom` — but D-10/§8.2 rule that `divided by` promotes to decimal, so the example is a compile error under the spec's own type rules (the annotated-`number`-receiving-decimal case). | 00 §13.1 example vs D-10/§8.2 | Contradiction between the error-model example and the number decision | D-10 wins (it is the deliberate, load-bearing decision: one number type, promotion on `divided by`, explicit `divided evenly by` escape). | G-15 | §7.0.3's greedy call-split rule splits a word run into head + tail (`say result` → `say(result)`) but does not say what span the synthetic tail argument gets. Applies to both split sites (name-split and callee-split). No grammar change. | Resolved (sema) |
| G-16 | §7.15's `call = name [arg1] {prep argN} …` production gives no AST home distinguishing prepositional reads from positional args, and §7.6's index read (`things at 2`) is spelled with the preposition `at`. | G-18 | §7.9's pair form (`a pair of A and B`, §7.6 type row) defines no element accessor: `first of` is specified over lists only (S-13), and §7.6's `last of` is unmentioned for pairs.
